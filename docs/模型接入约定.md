# PP-PicoDet 模型接入约定

组件源码和训练任务分别管理。模型从宿主提供的本地路径加载；组件不上传照片、不下载模型、不训练，也不把业务模型放进公开仓库。

## 交付文件

每版交付 `model.onnx`、`manifest.json`、训练与验证报告、权重及预训练来源许可说明。二进制应包含完整后处理，默认协议与 PaddleDetection 官方 PicoDet ONNX 带后处理导出一致。模型文件用 SHA-256 标识版本。

输入：

- `image`：float32，`[1,3,320,320]`，NCHW，RGB。
- 图像转为正确方向后，直接缩放至正方形（stretch，不做 letterbox）。
- 归一化：先除以 255；均值 `[0.485,0.456,0.406]`；标准差 `[0.229,0.224,0.225]`。
- `scale_factor`：float32 `[1,2]`，传入 `[[1,1]]`，让框保持在模型输入坐标系。
- 可使用 416 等正方形输入，manifest 的 `inputSize` 必须对应，接入前须重新跑双端性能测试。

输出：

- `multiclass_nms3_0.tmp_0`：float32 `[N,6]`，每行为 `[class_id,score,xmin,ymin,xmax,ymax]`。
- `multiclass_nms3_0.tmp_2`：int32 `[1]`，实际框数。演示修正版使用 `delivery_bbox_count`，通过 manifest 指定。
- 类别 ID 从 0 开始，与 manifest 的 labels 顺序一致。
- 坐标为输入图像像素，组件除以 `inputSize` 还原成完整竖屏画面的归一化框。输出名可通过 manifest 改写。
- 原始多尺度头、NCNN 文件、Ultralytics 输出或 letterbox 模型不能直接按此协议加载。

manifest 最小示例：

```json
{
  "name": "delivery-picodet-s-v1",
  "inputSize": 320,
  "labels": ["parcel_box", "parcel_bag", "insulated_bag", "beverage_case", "beverage_multipack", "delivery_crate", "bulky_delivery_item"],
  "boxesOutput": "multiclass_nms3_0.tmp_0",
  "countOutput": "multiclass_nms3_0.tmp_2"
}
```

以上为支持的类别命名，不要求训练时必须拆成七类；可按样本量合并类别，但须在 labels 中使用组件支持的对应名称或补充映射。不得单纯修改 labels，把未训练的 COCO 类别改名成纸箱、袋子或饮料。

## 配送物品范围

| 标识 | 外观范围 |
| --- | --- |
| parcel_box | 纸箱、封装箱 |
| parcel_bag | 购物袋、纸袋、软塑料配送袋 |
| insulated_bag | 保温袋 |
| beverage_case | 整箱饮料、整箱水 |
| beverage_multipack | 成提水、塑封多瓶饮料 |
| delivery_crate | 周转箱、配送筐 |
| bulky_delivery_item | 其他大件配送物品，例如大袋粮油、桶装物品 |

照片不能可靠判断重量，`bulky_delivery_item` 表示外观类别。整齐、倾倒或乱扔判断不在组件范围内。大件占画面较大不单独触发“太近”；只对明显裁切等情况建议给四周留出空间。

## 验证要求

按投递地点/任务分组拆分训练、验证、测试集，避免同一段视频或同一地点的近重复照片同时进入训练和测试。保留夜间、室内外、遮挡、多个物品、无包裹、背包/衣物等反例。清晰的远景照片也应纳入测试。

交付应说明各类召回率、误报、箱袋与整箱饮料的漏检、框的裁切，以及双端低配设备上的 P50/P95 单帧分析时间和连续使用发热。通用 COCO 准确率不能代替上述业务验证。

## 当前演示权重

`scripts/prepare_demo_models.py` 从 PaddleDetection 官方地址下载 S/XS 的 COCO 演示权重，校验固定 SHA-256，并移除旧导出里多余的常量输入声明、固定 batch=1、从实际 NMS 输出形状重建检测数量字段。未做业务训练、未改变类别。当前 COCO 类别不包含配送纸箱、软袋、整箱饮料、塑封提装饮料。

这些权重不随公共源码发布。仓库 Apache-2.0 是代码许可依据；尚未独立核实官方 checkpoint 的单独再分发声明，不把官方仓库的代码许可直接当作所有模型/训练数据的许可。生产模型应由接入方提供并核对完整来源。官方同类许可澄清问题：https://github.com/PaddlePaddle/PaddleDetection/issues/9493 。
