## 联调修复

- MethodChannel 的 Uint8List 不保证 float32 对齐，已添加对齐处理及回归测试。
- 官方旧 ONNX 文件的 bbox_num 返回候选锚点数，可能与 NMS 后的实际行数不一致。演示准备脚本从真实框输出形状重建数量字段，并通过桌面与 iOS 运行核对；业务端不静默截断异常输出。
- 相机预览和原始照片可能采用不同画幅。第一张拍摄时保留新鲜预览作为远景参考；不对最终照片做拍后合规复核。没有新鲜参考时保持待确认提示。
- 示例采用按架构输出 APK，避免把其他 CPU 架构的 ONNX/OCR 库带进 arm64 测试包。

## 尚未验证

- 没有连接的 Android 真机，因此 Android 相机、相册系统选择和连续推理尚未实机验证。
- 新运行时尚未在用户 iPhone 上执行完整双照片流程。此前旧引擎 Demo 的真机结果不算作本版验证。
- 老款 iPhone、低配 Android、长期发热、内存峰值、真实快门耗时和两张照片总耗时待测。模拟器纯推理时间不能当作手机性能承诺。
- 业务识别准确率等待独立训练任务交付模型。当前 COCO 通用演示权重没有配送纸箱、软袋、整箱饮料等专项类别，不能把框显示正常当作业务识别成功。
- 当前 iOS 最低 16.0、Android 最低 API 24。若生产 APP 需支持更低系统，必须先适配运行时，不能依靠一个设置开关解决静态依赖的最低系统要求。
